# Project: DigiWatch QR Battle, Background Evolution & Quick-Care

## Architecture
- **Multi-Module Layout**:
  - `:shared-vpet-core`: Pure Kotlin JVM library containing domain models (`PetSpecies`, `PetStage`, `PetState`), simulation engines (`PetSimulationEngine`, `EvolutionEngine`, `DeterministicBattleSolver`), codec (`CommCodeCodec` with HMAC-16), and QR matrix generation (`QrMatrixGenerator` via ZXing Core).
  - `:wear-os-app`: Android Wear OS standalone application containing Room database (`PetDatabase`, `PetRepository`), background decay worker (`PetDecayWorker`), piezo sound engine (`BuzzerManager`), haptic engine (`HapticManager`), pixel sprite matrix renderer (`PixelArtMatrices`), UI screens (`BattleScreen`, `MainPetScreen`), Complication service (`DigiWearComplicationService`), Tile service (`DigiWearTileService`), and background care receiver (`NotificationQuickCareReceiver`).
  - `:phone-companion-app`: Android Companion application containing Room database (`PhoneDatabase`), UI screens (`BattleHubScreen`), CameraX/MLKit scanner (`CameraBattleScanner`), Home Screen AppWidget (`DigiWearAppWidgetProvider`), and Wearable sync manager (`PhoneWearableManager`).

- **Data Flow & Cross-Module Contracts**:
  - Comm Code: 128-bit Base32 string with Crockford encoding and HMAC-16 checksum generated by `CommCodeCodec` in core, rendered as QR matrix via `QrMatrixGenerator` in core, displayed via Compose Canvas in both apps.
  - Camera Scan: Phone CameraX `ImageAnalysis` captures frames -> MLKit Barcode Scanning decodes QR rawValue -> `CommCodeCodec.decodeAuto()` verifies HMAC-16 -> instantiates `BattleFighter` -> populates `BattleHubScreen` opponent state and launches arena.
  - Background Evolution: `PetDecayWorker` runs periodically on Wear OS -> queries `repo.getPetState()` (`initialSpeciesId`) -> executes `repo.processDecay()` -> compares `finalSpeciesId != initialSpeciesId` -> posts `DIGITAL EVOLUTION!` notification with pixel bitmap and stage -> plays Bandai piezo buzzer sequence and vibration.
  - Notification Quick-Care: `PetDecayWorker` posts attention notification with `[ FEED MEAT ]` and `[ FLUSH WASTE ]` actions -> handled by `NotificationQuickCareReceiver` via `goAsync()` -> calls `repo.feedMeal()` / `repo.cleanWaste()` on `Dispatchers.IO` (Room write < 20ms) -> invalidates complications and tiles -> dismisses notification.

## Interface Contracts

### shared-vpet-core ↔ wear-os-app / phone-companion-app
- `com.digiwear.core.qrcode.QrMatrixGenerator`:
  - `fun generateQrMatrix(content: String, size: Int = 29): Array<BooleanArray>`
  - Generates boolean grid where `true` is black module, `false` is white.
- `com.digiwear.core.codec.CommCodeCodec`:
  - `fun decodeAuto(code: String): CommCodePayload`
  - Throws `IllegalArgumentException` on invalid HMAC-16 or invalid format.
  - Returns payload with `monsterId`, `stage`, `attribute`, `basePowerHp`, `historicalVictories`, `trainingEffort`, `battleRngSeed`.

### wear-os-app Notification & Receiver Contracts
- `NotificationQuickCareReceiver`:
  - `ACTION_QUICK_FEED = "com.digiwear.wear.action.QUICK_FEED"`
  - `ACTION_QUICK_CLEAN = "com.digiwear.wear.action.QUICK_CLEAN"`
  - Asynchronously updates `PetRepository`, notifies `ComplicationDataSourceUpdateRequester`, notifies `TileService.getUpdater`, updates/cancels notification.
- `PetDecayWorker`:
  - `CHANNEL_ID_EVOLUTION = "pet_evolution_channel"` (IMPORTANCE_HIGH)
  - `NOTIFICATION_ID_EVOLUTION = 1002`
  - `CHANNEL_ID_ATTENTION = "pet_attention_channel"` (IMPORTANCE_HIGH)
  - `NOTIFICATION_ID_ATTENTION = 1001`

### Sync Care Command Protocol Contract
- Canonical Actions: `"FEED_MEAL"`, `"CLEAN_WASTE"`
- Supported Fallback Aliases: `"FEED"`, `"CLEAN"`
